# Исследование попиксельного управления LEDDMX-00-698A

Цель первого этапа: доказать, что выбранные по номеру светодиоды независимо меняют цвет
на физической гирлянде. Анимация на экране или встроенный бегущий эффект этого не доказывают.

**Вывод:** в приложении LED LAMP для семейства LEDDMX-00/01/03 нет ни команды «цвет LED №N»,
ни передачи кадра, ни диапазонов. Кадр всегда 9 байт. Единственная «рисовалка» —
graffiti-кадры `7C … CF` — существует только для LEDDMX-02/04 и LEDCAR-02, их формат нигде не
описан. Отсутствие команды в приложении не доказывает, что её нет в прошивке, но и искать
её вслепую перебором нельзя.

## 2. Что означают DIY-команды

`7B <pos> 0E <FD|FE> R G B <total> BF` — цвет №pos в **палитре** пользовательской анимации
из total цветов (pos с 1, FD — скачком, FE — плавно). Затем `7B FF 0F 01 …` (старт по LED_UNION)
или `7B FF 13 <0…7>` (режим по user154lt: GD, FD, FW, FS, AC, PU, FL, HO).
Позиция в палитре ≠ индекс светодиода. Единственный интерес: вдруг один из 8 режимов
показывает палитру статично по сегментам — тогда появится посегментное управление.

## 3. Главная гипотеза: «защёлка» через конфигурацию числа пикселей

Контроллер по команде `05` узнаёт, сколько пикселей выводить. WS281x-светодиоды, которым
данные не пришли, **сохраняют последний цвет**. Если прошивка честно выводит ровно N пикселей:

1. `конфиг 200 px` + `чёрный` → всё гаснет.
2. `конфиг N px` + `красный` → горят LED 1…N.
3. `конфиг N−1 px` + `чёрный` → гаснут LED 1…N−1, **LED N остаётся красным**.
4. Повторить для M < N синим → LED N красный, LED M синий одновременно.

Это и есть критерий успеха. Скорость такой адресации низкая (4 кадра на светодиод, ≥100 мс
на кадр), но для **сканирования камерой достаточно**: нужно по одному разу зажечь каждый LED.

Что может пойти не так и что это означает:

| Наблюдение | Вывод |
|---|---|
| После `конфиг 10` + цвет горит вся лента | прошивка игнорирует число пикселей или всегда шлёт максимум — гипотеза не работает |
| Горят первые 10, остальные **гаснут** | прошивка дописывает чёрное до максимума — защёлка не работает, но число пикселей управляемо |
| Горят первые 10, остальные **держат прошлый цвет** | защёлка работает → шаги 3–4 |
| При `конфиг 1` горят 3 LED | один IC управляет группой из 3 — адресация по группам |
| Цвета перепутались | неверный код порядка каналов, вернуть `RGB` (код 1) |

## 4. Протокол физического теста (в приложении: иконка колбы)

Перед началом: закрыть LED LAMP, «Готово к управлению», живые эффекты остановлены.

1. **Откат** → убедиться, что «200 px RGB белый» даёт белую ленту целиком. Если цвета сдвинулись —
   код порядка неверен; попробовать другие в блоке 1 и записать, какой даёт RGB.
2. **Блок 1**: `Пикселей: 10` → Отправить конфигурацию → на главном экране выбрать красный.
   Записать, сколько LED горит и что делают остальные.
3. **Блок 2**: Шаг A → Шаг B (LED №1, красный). Записать, что горит. Затем LED №5, №50, №200.
4. **Блок 2**: Шаг C (второй LED другим цветом). Критерий: два LED, два цвета, одновременно.
5. Уменьшать «Паузу между кадрами» до тех пор, пока результат стабилен — это скорость
   адресации.
6. **Блок 3**: DIY-палитра R·G·B → перебрать режимы 0…7, записать, какие дают статичные сегменты.
7. **Блок 4**: включить встроенный эффект, двигать скорость — подтвердить команду `02`.
8. **Блок 5**: отправить `2A 05`, посмотреть, появился ли RX.
9. В конце — **Откат**, затем выключить/включить питание гирлянды и убедиться, что всё как раньше.

Журнал из диагностики (⋯ → «Поделиться») — приложить к результатам.

## Результаты физического теста (22–23.10.2026, LEDDMX-00-698A)

| Опыт | Наблюдение | Вывод |
|---|---|---|
| Конфиг `05`, N = 10 / 1 / 200 | Горят ровно первые N светодиодов, при N = 1 — один | Команда работает; адресация по одному LED, групп нет; всего 200 |
| Защёлка: N px красный → N−1 px чёрный | Все N вспыхивают и гаснут, в т. ч. N-й | Контроллер гасит всё за пределами N — защёлка не работает |
| DIY-палитра (`0E` + `0F`) | Принимается, режимы `13` 0…7 реагируют | Команды DIY подтверждены |
| DIY режим 0 | 6 LED одного цвета, плавная смена | временной |
| DIY режим 1 | Один цвет бежит 6→1, потом другой | временной + пробег, один цвет за раз |
| DIY режим 2 | Заливка: граница красный/синий движется по ленте | два цвета одновременно, но только как подвижная граница |
| Видео (4 ролика, режимы 3–7) | 1) заливка с движущейся границей; 2) все одного цвета с переходами; 3) все одного цвета; 4) один бегущий светодиод, один цвет | **ни один режим не раскладывает палитру статично по ленте** |

**Итог первого этапа:** через родной BLE-контроллер независимо задать цвет выбранному по
номеру светодиоду не удалось. Подтверждено: прошивка умеет выводить ровно N пикселей и
умеет держать разные цвета на разных LED (заливка, бегущий пиксель), но ни одна известная
команда не даёт этого выбирать. Исследованы все команды семейства `7B FF` из LED LAMP 4.3.5,
конфигурация числа пикселей, защёлка, 8 DIY-режимов, скорость.

Что всё-таки даёт родной контроллер для карты: «N пикселей + цвет» зажигает LED 1…N, и разность
кадров камеры для N и N−1 выделяет LED N. Так можно построить карту индекс → x,y без
попиксельной команды (≈200 шагов, 1–2 минуты). Но без попиксельной команды карта почти
бесполезна — только «заливки по форме».

## 6. Декомпиляция LED LAMP 4.3.7 (24.10.2026)

Скачан актуальный APK `com.ledlamp` 4.3.7 (разработчик tanguixing / Shenzhen Zhongji), разобран
jadx. Проверено по `com/home/net/NetConnectBle.java` и `MainActivity_BLE.java`:

**Что LED LAMP даёт именно LEDDMX-00** (sceneBean `LEDDMX-00-`): `ModeFragment` (211 эффектов),
`CutomFragmentDmx00Dmx01` (DIY-палитра `0E` + режим `13`), кнопки «подзона» центр/лево/право
(`7B FF 14 <0|1|2>`, показываются только для DMX-00/01), «канал» 1…4 (`7B FF 11 <0…3>`),
цикл режимов (`7B <i> 12 …`), пауза эффекта (`7B FF 06 <x>`), музыка. **Экрана graffiti для
DMX-00 нет.**

**Graffiti существует** для LEDDMX-02/04/06 и LEDCAR-02 (`CutomFragmentDmx02Dmx04`):

```
7C <mode> R G B idxHi idxLo FF CF
mode: 0 кисть (задать пиксель), 1 ластик, 2 очистить всё (в idx — общее число), 3/4 — без подписи
idx:  0-based, в приложении до 200 пикселей; одномерная «лента», не матрица
пауза между кадрами в приложении: 100 мс
```

Это ровно то, что нужно (200 пикселей, цвет по индексу), но для другого семейства контроллеров.
Раскладка остальных кадров у DMX-02/04 сдвинутая (`7B 07 R G B …` без `FF`), т. е. прошивка
другая; примет ли наша прошивка `7C` — решает только физический тест (блок 0 лаборатории).

### Результаты проверки команд из декомпиляции (24.10.2026)

| Кадр | Что делали | Наблюдение | Вывод |
|---|---|---|---|
| Graffiti `7C 00 R G B idx FF CF` | гасили ленту, рисовали пиксели 0/5/10; затем `02`, `00`, `03`, `04`, `7B 0E` | лента погасла и больше **никакой реакции** | прошивка LEDDMX-00 кадр `7C` не понимает — закрыто |
| Подзона `7B FF 14 <0/1/2>` | лево/право/центр, затем цвет с главного экрана | каждый раз красится **вся** лента | на этом экземпляре не действует |
| Канал `7B FF 11 <0…3>` | при идущем эффекте №2 | 1 — другой бегущий эффект; 2 — мигание по частям; 3 — ничего; 0 — стробоскоп, затем смешанное состояние | переключает вариант отрисовки эффекта, не часть ленты; состояния странные — не использовать |
| Пауза `7B FF 06 <x>` | при идущем эффекте №2 | `01` — эффект **замер**, `00` — продолжил | **подтверждено**, вынесено на главный экран |

**Окончательный итог по родному контроллеру:** все известные команды LED LAMP 4.3.7 для
семейства `7B FF` и graffiti-кадр `7C` испытаны. Независимо задать цвет светодиоду по номеру
нельзя. Дальше — только снифф трафика ради подтверждения (нового в приложении для DMX-00 нет)
или ESP32 на линии DAT.

## 7. Итог: попиксельное управление получено через ESP32 + WLED (24.10.2026)

Родной контроллер исчерпан; гирлянда переведена на ESP32 с WLED 16.0.1 — см. `ESP32.md`.
Подтверждено: 200 адресуемых WS281x-пикселей, порядок RGB, независимый цвет по номеру LED,
40 fps по DDP. Дальше — второй этап: карта камерой и эффекты по форме (поверх WLED/DDP).

## 5. Если доступ к отдельным LED не подтвердится

Исследовано будет: все команды LED LAMP для семейства `7B FF`, поведение конфигурации числа
пикселей и защёлки, 8 DIY-режимов, канал уведомлений. Следующие варианты:

- **Снифф трафика LED LAMP** на Android (HCI snoop log) при смене настроек «чип / число LED» —
  вдруг приложение шлёт кадры, которых нет в декомпиляте (например, `7C`).
- **ESP32 + WLED** на линии DAT: у нас есть DevKit с WLED 16.0.1 и выбран GPIO18. Это даёт
  полноценное попиксельное управление по Wi-Fi (DDP/UDP-реалтайм, 200 LED при 30+ fps), и
  карта камерой становится тривиальной. Не проверены: протокол линии DAT (WS2811/WS2812 на 5 В?),
  уровень сигнала 3,3 В → 5 В, питание. Первый шаг — осциллограф/логический анализатор на DAT
  родного контроллера или просто попробовать WS2812B-профиль в WLED с 1 LED.
